# Migration decisions

These are implementation choices for the proposed product. Validate them at the gates in PLAN.md.

- **One local core.** The hosted API couples repository creation to provider readiness and a background pipeline. Independent commands need a callable core with explicit ingestion and generation operations. Keep demo deployments on their own entry points and package dependencies.
- **Durable bytes and immutable references.** Store deduplicated bytes in SQLite to commit source and metadata together. This costs local disk space but makes backup, offline citations and crash recovery tractable. Changed refresh returns a new session so a saved conversation never silently changes evidence.
- **Lexical retrieval first.** Index chunks by path and body. SQLite FTS5 supplies BM25 ranking and supports virtual tables. Exact source reads only depend on the file/blob store. Test FTS at runtime because SQLite builds vary. [SQLite FTS5](https://www.sqlite.org/fts5.html)
- **User directories and packaging.** Use platformdirs for portable data, configuration and cache locations. Define the executable and extras in root package metadata; validate constraints using the installed distributions in each implementing phase. [platformdirs](https://platformdirs.readthedocs.io/en/latest/) · [Python packaging guide](https://packaging.python.org/en/latest/guides/writing-pyproject-toml/)
- **Command and terminal adapters.** Typer command groups map to use cases. Textual headless tests can drive keyboard events through Pilot, complemented by a real terminal smoke. [Typer commands](https://typer.tiangolo.com/tutorial/commands/) · [Textual testing](https://textual.textualize.io/guide/testing/)
- **Git discovery.** Tracked and untracked enumeration requires separate Git flags. Use NUL delimiters for unusual names, Git's standard excludes for untracked inputs and independent hard exclusions for sensitive paths. [Git ls-files](https://git-scm.com/docs/git-ls-files)
- **Strict offline.** Disable all transports for inference in offline mode, including loopback. Users can explicitly run a local model in ordinary generation mode. Opening existing sessions and exporting content require only storage.
- **Standalone generation.** Normalize streamed provider events in the adapter. Ollama supports incremental NDJSON over HTTP. Preserve provider-reported usage when available and test cancellation per adapter. [Ollama streaming](https://docs.ollama.com/api/streaming) · [OpenAI Python SDK](https://github.com/openai/openai-python) · [Anthropic streaming](https://platform.claude.com/docs/en/build-with-claude/streaming)
- **Host-owned generation.** Use the official Python MCP server/client SDK over stdio. Test the resolved release with a real subprocess before documenting host configuration. Save only explicitly submitted host output with host provenance and return a durable receipt. [Official MCP Python SDK](https://github.com/modelcontextprotocol/python-sdk)
- **Hosted history.** Legacy rows can contain truncated file bodies and repository-level chat from different analysis runs. A future explicit importer must mark unknown provenance, preserve original text and exclude admin/configuration records. Never manufacture citations or treat imported content as a verified cache hit.

## Phase 1 implementation

- Public GitHub inputs use the anonymous commit endpoint followed by the tarball endpoint at the returned SHA. This supports explicit refs, bounds compressed and expanded bytes, and avoids writing a checkout or invoking Git credential helpers. Archive coverage follows GitHub export rules. [GitHub commits](https://docs.github.com/en/rest/commits/commits#get-a-commit) · [GitHub archives](https://docs.github.com/en/rest/repos/contents#download-a-repository-archive-tar)
- Local traversal uses POSIX descriptor-relative opens and top-down pruning. Git check-ignore filters one directory at a time; a tracked descendant keeps an otherwise ignored directory eligible. Local Git transport is disabled. This preserves working-tree content and limits discovery to the selected directory.
- The first schema is a transactional migration from an empty store. Immutable source bytes, chunk text and search postings commit together. Captures with identical identity reuse the snapshot. The bounded missing-FTS fallback scans only the selected snapshot and returns stable path/line order.
- The tested installation used Python 3.13, setuptools 84.2.1, Typer 0.29.2 and platformdirs 4.14.8. The local distribution name is provisional pending Phase 5 publication review.

## Phase 2 implementation

- The two HTTP adapters share a text/usage/completion event interface using the standard library. OpenAI uses Chat Completions SSE with explicit terminal status; Ollama uses NDJSON on an explicitly local runtime. The provider module is imported only when a generation actually needs inference. Model IDs are supplied by the user. [OpenAI Chat Completions](https://platform.openai.com/docs/api-reference/chat/create) · [Ollama chat](https://docs.ollama.com/api/chat)
- Schema v2 saves each generation attempt as a record containing checkpoint text, evidence excerpts, identity, usage and status. Artifact links select versions per session. The message view presents the persisted question and assistant result as ordered turns. The session lock protects conversation order while allowing short SQLite writes between network reads. Kernel lock release on process death lets the next reader classify a stale running attempt.
- Cache hashes include the actual assembled request, selected source, snapshot, prompt version and provider settings. Completed artifacts can be linked across sessions on the same snapshot. Chat uses explicit request-ID replay only. Invalid citations and incomplete streams retain failed attempts and are excluded from completed hits.
- Source selection ranks durable passages with section-specific terms and chooses bounded line windows. A conservative input byte budget and separate provider output-token cap avoid a tokenizer dependency; model-specific context-window errors are surfaced to the caller. Citation checks verify that references belong to selected source. They cannot verify all claims in generated prose.
